# Monkey Paradox
This is a typing practice platform where you can not only get better with your typying abilities but also have some fun trying to break your own personal records and see how far you can get.
#### Video Demo:  [https://youtu.be/clj2viFmG0Q](https://youtu.be/clj2viFmG0Q)
#### Description:

As i said before this is a typing practice platform that adds some extra things that a regular typing practice application have like a system of points that can later on be use as a fuel to keep competing and be better at this practice. This application have sound managment with some cool effects for the points and a really cool profile view that i will improve while the time pass by.

This project is create with React with zustand to the managment of states across the different components and views of the aplicattion , the reason why I use zustand its because I think is simplier than reduz and help a lot with the modular structure of the application. Also the back is created with go, 'cause I didn't know about back application development with go and I wanted to use this project to learn about it, just as a personal challenge to get better with a tecnology that I did never use.

Talking more about infrastructure this types of application use something called MVC architecture that is basically a pattern where you have this principal instances of a model that its responsible for the queries and details about every table of the database that you choose, this model is connected to a controller to helps a lot with the programming logic in the application and then it sends to a router who sends the required data to the Views. Now, for this project i wanted to use something called Hexagonal Architecture or Clean Architecture. This type of pattern helps a lot to separate the internal logic operations to the database operations principally to avoid errors and simplyfing debugging process. If you look into the internal folder you can see a lot of more folder that holds one responsabilities and all of them end it up connected. The _repo is call by the service of the domain, the service is call by a handler that would be the controller in the MVC pattern, and the handler its use for the router. The router gives the endpoints, endpoints that can be protected or not. I implemented authentication and autorization, obviosly for the user managment and for the future competitive features I need to handle the authentication and autorization of the views and the endpoints, things of security. For that I use JWT and cookie managment. Before this project I've use the localstorage as a space to save the token of the application but reading I see that is safer if I just handle that with the cookies of the browser.

Aside from all that the project itself is a monolith, is a single contain folder with all the code that it need to function. I thought it would be a great idea since this should be a personal little project and later when I have to deploy it I think it would be better.

For the future, no longer of the next year, my expectations to this project are just keep coding of this, on the multiplayer and keep adding more details, there is always thing to put on a product, specially if this product is an application.
